# Windows Local Account Creation Detection

## Overview

This scenario validates Wazuh detection of a newly created Windows local user account. A temporary account was created on the monitored Windows endpoint, generating Windows Security Event ID 4720.

Wazuh received the event and generated a level-8 alert using its built-in rule `60109`.

## Lab Environment

| Component | Details |
|---|---|
| Monitored endpoint | Windows 10 VM |
| Wazuh agent | `WindowsUser` |
| Agent ID | `003` |
| Endpoint IP in observed alert | `10.0.2.15` |
| Event source | Windows Security log |
| Windows event ID | `4720` — A user account was created |

## Test Procedure

A temporary local account named `wazuh_lab_test` was created from an elevated PowerShell session.

```powershell
$password = ConvertTo-SecureString "LabTest-2026!Temp" -AsPlainText -Force
New-LocalUser -Name "wazuh_lab_test" -Password $password -Description "Temporary Wazuh detection lab account"
```

The Windows Security log was checked for Event ID 4720:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id = 4720
} -MaxEvents 5 | Select-Object TimeCreated, Id, ProviderName, Message
```

The event was present in the Windows Security log and was also visible in Wazuh Discover.

## Detection Results

| Field | Observed value |
|---|---|
| Windows event ID | `4720` |
| Created account | `wazuh_lab_test` |
| Initiating account | `b82g1` |
| Wazuh rule ID | `60109` |
| Alert level | `8` |
| Rule description | User account enabled or created |
| Wazuh alert index | `wazuh-alerts-4.x-2026.10.26` |
| MITRE technique ID | `T1098` |
| MITRE technique | Account Manipulation |
| MITRE tactic | Persistence |

The alert included the target account, the initiating account, the Windows computer name, and account attributes.

## Validation

To locate the event in Wazuh Discover:

```text
data.win.system.eventID: "4720" AND agent.name: "WindowsUser"
```

To locate alerts generated by the built-in detection rule:

```text
rule.id: "60109" AND agent.name: "WindowsUser"
```

## Account Attribute Verification

After creation, the account was inspected using `Get-LocalUser`.

Observed values:

| Property | Value |
|---|---|
| Name | `wazuh_lab_test` |
| Enabled | `True` |
| PasswordRequired | `False` |
| PasswordLastSet | `10/26/2026 9:40:50 PM` |
| SID | `S-1-5-21-239370383-613643671-2187736164-1004` |

The Event 4720 message also reported the account attribute `'Password Not Required' - Enabled`.

The temporary test account was intended only for this lab scenario and should be removed after evidence collection.

## MITRE ATT&CK Mapping

- **Tactic:** Persistence
- **Technique:** [T1098 — Account Manipulation](https://attack.mitre.org/techniques/T1098/)

This is the mapping supplied by the observed Wazuh alert. Account creation can have several possible purposes; the event alone does not establish malicious intent.

## Detection Limitations

- This scenario validates the built-in Wazuh rule `60109`; it does not implement a custom detection rule.
- Legitimate administrators also create local accounts, so an account-creation event is not proof of malicious activity.
- This test validates detection of local account creation. It does not demonstrate detection of every account modification or privilege escalation.
